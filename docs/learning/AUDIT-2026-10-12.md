# 공통 피드백·자가 개선 전후 점검

점검일: 2026-10-12 KST. 대상: Sites `soullab-tools`, GitHub `eco-nika/soullab-tools`, 현재 ChatGPT Work 실행 환경.

## 결론

점검 전 운영 DB는 목표 1개·피드백 5개·피드백 벡터 5개가 모두 예제였습니다. 실제 사용자 피드백 저장·다음 작업 전달·출력 반영·성과 개선은 연결되지 않았습니다.

이번 작업에서 공통 지침/인계, 선별 저장, 범위별 조회, 반영 근거, 비교·승격 경로를 소스에 구현했습니다. **운영 적용은 하지 않았습니다.** 소스 완료와 실제 운영·성과 검증은 다릅니다. 이 제한 때문에 이번 개선 작업을 미완료로 막지 않습니다.

## 확인한 근거

- Sites DB overview: `agent_learning_goals`, `agent_learning_feedback`, `agent_learning_feedback_embeddings`, `knowledge_embeddings`, `test_orders` 존재.
- 목표 1건과 피드백 5건 모두 `is_sample=1`. 페이지 끝까지 조회(`has_more=false`)하여 실제 사용자 피드백 0건 확인.
- 기존 `server/learning-data.mjs`가 가상 예제임을 명시. `ensureKnowledge`가 예제를 INSERT OR IGNORE로 등록.
- 기존 `/api/admin/learning`은 GET 조회 전용. 쓰기 경로·범위 필터·개선 승격 없음.
- 기존 `answerQuestion`은 `knowledge_embeddings`만 검색. feedback embeddings는 답변/작성에 사용되지 않음.
- 기존 `/api/chat`은 검색 원문을 반환하며 질문·결과를 학습 기록으로 저장하지 않음.
- `get_site(include_mcp_connection=true)`는 published Site에 MCP 선언이 없음을 반환.
- GitHub와 Sites 시작 소스의 모든 파일 경로/해시 일치. GitHub CLI fetch도 성공. 두 저장소의 커밋 이력은 다름.

## 저장·조회·반영·성과 구분

| 단계 | 검증 내용 | 현재 결과 | 증명하지 않는 것 |
| --- | --- | --- | --- |
| 저장 | SQLite에 추가 마이그레이션 적용, run/feedback/vector 저장, 재시도·중복 | 통과 | 운영 DB 저장 |
| 조회 | 예제 제외, 범위/대상 분리, 승격·비활성화 필터 | 통과 | AI가 실제로 읽고 이해함 |

인용 일치 검사는 문구 존재만 확인합니다. 맥락 적합성은 검토자가 확인해야 합니다. 실험의 evidence_ref는 제출된 근거 위치이며, 이 버전이 외부 분석 서비스에서 원자료를 자동 수집·독립 감사하지는 않습니다.

## 실행 검증

- `node --test tests/*.test.mjs`: 전체 32개 통과(기존 18개 + 신규 14개).
- 실제 SQLite에서 기존 마이그레이션을 순서대로 적용하고 신규 테이블/벡터/참조 검증. 운영 DB를 복제하거나 대체하지 않음.
- production build: 새 `/api/agent-learning`, `/mcp` 라우트 포함 성공.
- `node automation/learning/source-status.mjs`: GitHub main fetch 성공, 초기 두 소스 트리 동일 확인, 현재 수정 중 dirty 표시.
- 공통 client context: Git 지침 8개 로드. 비밀 미설정 시 `Learning URL/token not configured`, `retrieval:false` 표시 후 정상적으로 작업 자료 제공.
- 공통 client run: 미설정 시 `stored:false`, `task_may_continue:true`; 성공으로 위장하지 않음.
- 인증 검증: HTTP 미설정 503·잘못된 토큰 401, MCP 미설정 503·다른 사용자 403, 정상 설정은 핸들러 통과.
- 변경 사항은 서버·문서 중심으로 브라우저 UI 검증은 수행하지 않음.

## 남은 제약과 후속 적용

- 사이트 재게시 없음: 새 DB 테이블, 실제 저장 API, MCP 플러그인 연결은 운영에 적용되지 않았음.
- 토큰과 Site별 소유자 ID를 실제로 설정하지 않음. 재사용 가능한 비밀값을 문서에 넣지 않음.
- 해싱 검색은 의미·동의어 이해에 한계. 동일 범위가 5,000행을 넘으면 불완전한 검색 대신 명시적 오류를 반환하며 본 작업은 계속할 수 있음. 성장 시 인덱스·보관 정책 개선 필요.
- 피드백의 의미 중복 자동 병합, 만료/삭제 자동화, 외부 성과 수집, 각 앱의 자동 시작 hook은 포함하지 않음. 최신성 확인과 컨텍스트 사용은 공통 지침을 따르는 에이전트가 실행함.
- 모델 파라미터 재학습이 아니라 외부 기억·피드백·평가 절차를 통한 개선임.
- 이후 배포 시 실제 결과 1건→사용자 확정 피드백→다른 환경 조회→실제 출력 인용까지 먼저 확인한 뒤 성과 비교를 시작할 것.
